# Evaluation baselines

Each file in `baselines/` is the `report.json` of one real run of a canonical evaluation suite: what was measured
(word and character error rates overall and per accent, region and language, language errors, speed) together with
everything that can change those numbers: the model's profile, variant and fingerprint (the SHA-256 manifest of its
files), the decoding settings, the dataset fingerprint (the audio and references of every item), Mneme's version and
the machine.

| File | Suite |
|---|---|
| `say-reference.<model>.json` | macOS voices, decoded in the reference language: accent robustness alone |
| `say-detect.<model>.json` | the same voices with language identification over all languages: accents mistaken for another language |
| `codeswitch-sentence.<model>.json` | sentences in French, English, German and Arabic switching within a recording, one language per sentence |

## Rules

1. **Baselines come from real runs, never from hand edits.** `bash Scripts/model-check.sh baseline` (or
   `baseline accurate`) runs the suites and copies each `report.json` here; review the diff, then commit it with the
   reason in the message.
2. **A change to the speech pipeline passes the gate before it merges.** `bash Scripts/model-check.sh gate` runs the
   same suites with `mneme eval --gate` against these files. Exit 0: passed; 1: refused (a regression or a missed
   bar, listed in `gate.md`); 2: the run itself failed.
3. **Comparisons hold only on the same data.** The audio comes from the voices installed on the Mac that made the
   baseline. On other data the dataset fingerprint differs and the gate applies its absolute bars only: no failed
   items, overall WER at most 10 %. On GitHub's runners this is the case for the accent suites, whose voices differ;
   the code-switching suite's named voices produced byte-identical audio there, so it is compared in CI too.
4. **Promotion is a human decision.** To make another model the default, run the suites with it (`mneme eval … --model
   <candidate> --gate baselines/<suite>.fast.json`): the gate compares the challenger with the champion and notes that
   the model differs. If it passes, change `ModelProfile.defaultProfile`, regenerate the baselines and commit both.

The data itself (`eval/`) is generated by `Scripts/make-say-samples.sh` and `Scripts/make-codeswitch-samples.sh` and is
not committed: synthetic voices are a check of the pipeline, not a measure of real accented speech. See
[docs/MLOPS.md](../docs/MLOPS.md).
